# routewire

A fork of [wg-easy](https://github.com/wg-easy/wg-easy) that replaces the in-container WireGuard daemon with a [MikroTik RouterOS](https://mikrotik.com/software) backend.

All WireGuard configuration is managed through the web UI and pushed to the router via the RouterOS REST API. The container itself requires no Linux network privileges.

---

## How it works

| Concern | Handled by |
|---------|-----------|
| WireGuard interface & peer state | RouterOS (MikroTik device) |
| Interface IP addresses | RouterOS (`/ip/address`, `/ipv6/address`) |
| Server keypair generation | routewire (on first boot, pushed to RouterOS) |
| Client keypair generation | routewire (private key stays client-side) |
| Client config & QR code rendering | routewire |
| Live stats (rx/tx, last handshake) | Proxied from RouterOS REST API |
| Web UI, client database | routewire (SQLite) |

On every config change the container calls the RouterOS REST API to create, update, or remove peers. No `wg-quick`, no iptables, no kernel modules.

---

## Requirements

### MikroTik device
- RouterOS 7.1 or later (WireGuard support)
- REST API enabled (`/ip/service` → `www-ssl` or `www`)
- A dedicated API user with limited permissions (see below)
- A WireGuard interface already created, or let routewire create it on first boot

### Container host
- Docker (any host, no special kernel requirements)
- Network access to the RouterOS REST API port (default 443)

## RouterOS setup

### 1. Create a dedicated API user

In RouterOS terminal:

```
/user/group/add name=wireguard-api policy=read,write,api,rest-api
/user/add name=wireguard-api group=wireguard-api password=changeme
```

### 2. Enable the REST API

The REST API is served on the same port as the web interface (`www-ssl` on port 443 by default). Make sure it is enabled:

```
/ip/service/set www-ssl disabled=no
```

> If you use a self-signed certificate (common in home labs), set `ROUTEROS_VERIFY_SSL=false`.

### 3. WireGuard interface

routewire will create the interface automatically on first boot if it does not exist. If you prefer to create it manually:

```
/interface/wireguard/add name=wg0 listen-port=51820 mtu=1420
```

The server keypair is generated by routewire and pushed to the interface on startup. The private key is stored in the routewire database and is the authoritative source.

## Quick start

```yaml
# docker-compose.yml
volumes:
  routewire_data:

services:
  routewire:
    image: ghcr.io/your-org/routewire:latest
    container_name: routewire
    environment:
      - ROUTEROS_HOST=192.168.1.1
      - ROUTEROS_USER=wireguard-api
      - ROUTEROS_PASSWORD=changeme
      - ROUTEROS_INTERFACE=wg0
      - ROUTEROS_VERIFY_SSL=false
    volumes:
      - routewire_data:/etc/wireguard
    ports:
      - "51821:51821/tcp"
    restart: unless-stopped
```

```bash
docker compose up -d
# Open http://<host>:51821
```

No `cap_add`, no `sysctls`, no `/lib/modules` mount needed.

## Environment variables

### RouterOS backend (required)

| Variable | Default | Description |
|----------|---------|-------------|
| `ROUTEROS_HOST` | — | IP or hostname of the MikroTik device |
| `ROUTEROS_USER` | `admin` | RouterOS API username |
| `ROUTEROS_PASSWORD` | — | RouterOS API password |
| `ROUTEROS_INTERFACE` | `wg0` | WireGuard interface name on RouterOS |
| `ROUTEROS_VERIFY_SSL` | `false` | Verify the RouterOS TLS certificate |

### Web UI

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `51821` | Port the web UI listens on |
| `HOST` | `0.0.0.0` | Bind address |
| `INSECURE` | `false` | Serve UI over plain HTTP |
| `DISABLE_IPV6` | `false` | Disable IPv6 support |

### First-boot initialization (optional)

These are applied once when the database is first created.

| Variable | Description |
|----------|-------------|
| `INIT_ENABLED` | Set `true` to apply the values below |
| `INIT_USERNAME` | Admin username |
| `INIT_PASSWORD` | Admin password |
| `INIT_DNS` | Default DNS for clients (comma-separated) |
| `INIT_IPV4_CIDR` | VPN IPv4 subnet, e.g. `10.8.0.0/24` |
| `INIT_IPV6_CIDR` | VPN IPv6 subnet, e.g. `fd42:42:42::/64` |
| `INIT_ALLOWED_IPS` | Default allowed IPs for clients |
| `INIT_HOST` | Public hostname/IP clients use to connect |
| `INIT_PORT` | WireGuard listen port advertised to clients |

## Data persistence

All state is stored in `/etc/wireguard/wg-easy.db` (SQLite) inside the container. Mount a named volume or host path to persist it across restarts.

RouterOS is the live source of truth for the running WireGuard state. The routewire database is the authoritative source for keypairs and configuration — on every startup the full config is pushed to RouterOS.

## Migrating from wg-easy

If you have an existing wg-easy installation, you can migrate all clients without reconfiguring any of them. The server keypair is restored from the old config so existing clients continue to connect immediately.

### What you need

- The old `wg0.json` (wg-easy v2/v3 flat-file format), placed at `migration/wg0.json`
- Python 3.9+ (stdlib only, no dependencies)

### Steps

**1. First boot — create the database without RouterOS**

Start routewire once with `INIT_*` vars set but **without** `ROUTEROS_HOST`, so the container builds the database schema and admin account before the migration runs:

```yaml
environment:
  # ROUTEROS_HOST intentionally omitted
  - INIT_ENABLED=true
  - INIT_USERNAME=admin
  - INIT_PASSWORD=yourpassword   # minimum 12 characters
  - INIT_HOST=vpn.example.com
  - INIT_PORT=51820
  - INIT_IPV4_CIDR=10.8.0.0/24
  - INIT_IPV6_CIDR=fd42:42:42::/64
  - INIT_DNS=1.1.1.1,1.0.0.1
  - INIT_ALLOWED_IPS=0.0.0.0/0,::/0
```

```bash
docker compose up   # wait for "Listening on ..." then Ctrl+C
```

**3. Run the migration script**

Copy the database out of the volume, run the script, copy it back:

```bash
# Copy DB out
docker run --rm \
  -v routewire_etc_wireguard:/data \
  -v $(pwd)/migration:/out \
  alpine cp /data/wg-easy.db /out/

# Preview what will be imported (no changes written)
python3 migration/migrate.py \
  --json migration/wg0.json \
  --dry-run

# Run migration
# IPv4 CIDR is inferred as /24 from the server address in wg0.json.
# Pass --ipv6-cidr if your old setup had IPv6, --port if not 51820.
python3 migration/migrate.py \
  --db migration/wg-easy.db \
  --json migration/wg0.json \
  --port 51820 \
  --ipv6-cidr fd42:42:42::/64

# Copy DB back
docker run --rm \
  -v routewire_etc_wireguard:/data \
  -v $(pwd)/migration:/out \
  alpine cp /out/wg-easy.db /data/
```

**4. Start normally with RouterOS**

Add `ROUTEROS_HOST` back and restart. routewire will push the migrated config (including the restored server keypair and all peers) to RouterOS on boot:

```bash
docker compose up -d
```

Verify peers appeared on the router:
```
/interface/wireguard/peers print
```

The script is idempotent — safe to re-run if something goes wrong.

## Differences from wg-easy

| Feature | wg-easy | routewire |
|---------|---------|-----------|
| WireGuard daemon | In container | RouterOS device |
| Required capabilities | `NET_ADMIN`, `SYS_MODULE` | None |
| `/dev/net/tun` | Required | Not required |
| Firewall rules (iptables) | Managed by container | Managed by RouterOS |
| AmneziaWG support | Yes | No |
| Target hardware | Any Linux host | MikroTik + RouterOS 7.x |
